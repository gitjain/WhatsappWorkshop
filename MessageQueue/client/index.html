How This Demo Works

Your Browser RabbitMQ Workers │ │ │ │ POST /api/task │ │ │─────────────────────────────────▶│ │ │ │ │ │ Returns IMMEDIATELY │ Message in Queue │ │◀─────────────────────────────────│─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─▶│ │ (status: "queued") │ │ │ │ │ │ │ Worker picks up message │ │ │◀────────────────────────────│ │ │ │ │ │ Processing... │ │ │ [Working]│ │ │ │ │ │ ACK (done) │ │ │◀────────────────────────────│ │ │ Message removed │

Key concepts demonstrated:

1. Async Processing: Producer returns immediately, doesn't wait for work to complete
2. Competing Consumers: 3 workers compete for tasks - each task goes to ONE worker
3. Persistence: Messages survive RabbitMQ restarts (durable queue)
4. Acknowledgment: Messages only removed after successful processing

Try these experiments:
1. Submit 1 task - watch a single worker process it
2. Burst 10 tasks - see how they distribute across workers
3. Submit slow task - other tasks continue processing in parallel
4. Open RabbitMQ UI (guest/guest) to see the queue
